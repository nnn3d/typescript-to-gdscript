# Project Structure & Implementation Notes

Detailed project layout, implementation status, conversion rules, and edge cases. See AGENTS.md for instructions/rules.

## Documentation Layout

User-facing docs are split between `README.md` and `docs/`:

- `README.md` — quick-start: tagline + before/after snippet, why-use-it, install + `tstogd init`, manual config pointer, essential CLI, brief transform rules (one class per file, types, imports), `gd` helpers cheat sheet. Designed so a new user doesn't need to open `docs/` to ship a working project.
- `docs/configuration.md` — full `tstogd.json` + `tsconfig.json` reference, shared-package linking, and addon naming rules
- `docs/transform-rules.md` — every TS-construct → GDScript mapping: primitive type case mapping, operators, comments (incl. `/* */` → `"""..."""`), constructor, async + `Promise<T>` return unwrapping, Callable `.call()` rewrite, `this`/`self`, constants & static fields, enums (file-scope + class-scope via namespace), inner classes (namespace merging), decorators / annotations (bare + `@gd.*` forms, `@exports` plural rule), abstract classes, signal named-tuple labels, strings & template literals, GD-side shorthand literals (`&`, `^`, `$`, `%`, `:=`), `super` calls, GD→TS implicit `this.` insertion, member ordering, logical operators (both directions), anonymous-class convention, imports → preload, **Restrictions section** (destructuring, for...in, `??`/`?.`, spread, `var`, file-scope decls, multiple classes, missing extends, default/namespace imports, `undefined` type, string enums, Promise misuse, `in` on value/packed types, `gd.dict` / `gd.getset` constraints)
- `docs/cli.md` — every CLI command and every flag (`init`, `convert`, `watch`, `clear-cache`, diagnostic modes); links to specialized commands in their own files
- `docs/gd-helpers.md` — full `gd` namespace reference (semantics, rules, edge cases for every helper)
- `docs/gd-to-ts-migration.md` — `initial-convert-gd-to-ts` + the 5 conversion helpers (signal handler, operator fix, explicit convert, extends type, nullable, ready field types)
- `docs/typings.md` — `generate-typings`, `generate-gdscript-global-typings`, `generate-addon-typings` + typings tree layout + scene typings features + nullable reference types. (No `generate-class-typings` command exists — global class declarations are produced by `generate-typings` via `converterOptions.generateGlobalClassTypes`.)
- `docs/ide-integration.md` — TypeScript language service plugin + `tstogd open-editor` + Godot external-editor configuration
- `docs/development.md` — contributor info: prerequisites, test scripts, regenerating Godot typings

When adding a new feature or CLI flag, update the corresponding `docs/*.md` file (and the README if the feature is user-essential).

## Tech Stack

- **Package manager**: yarn (v1)
- **Build**: plain tsc (ES modules, Node16 resolution, ES2022 target, `erasableSyntaxOnly: true`)
- **Testing**: vitest (fixture-based paired .ts/.gd files)
- **TS parsing**: TypeScript Compiler API (ts.Program + TypeChecker for type-aware transforms)
- **GD parsing**: tree-sitter + tree-sitter-gdscript v6.1.0
- **Godot resource parsing**: tree-sitter-godot-resource v0.7.0 (.tscn, .tres, project.godot)
- **AST type generation**: @asgerf/dts-tree-sitter v0.21.0 (generates typed AST interfaces from grammars)
- **Source maps**: `source-map` npm package
- **CLI**: commander, **Watch**: chokidar, **Cache**: ProjectCache (MD5-based content hashing, inline source maps + diagnostics in `cache.json`, `.gd` mirror at `<cacheDir>/gd-output/`, atomic tmp-rename writes)

## CLI Commands (binary: `tstogd`)

- `tstogd init` — Interactive project initialization (tstogd.json, tsconfig.json with ts-plugin enabled, npm install, .gdignore)
- Global flag: `--debug` (placed before any subcommand) enables verbose info/debug messages via `setDebugEnabled(true)` in the `preAction` hook.
- Global flag: `-V` / `--version` prints the package version, read from `package.json` via `getPackageVersion()` (`src/utils/package-version.ts`) — the same helper the cache uses for its manifest version, so the two can never drift.
- `tstogd convert <files...>` — Synchronize shared-package links, convert TS to GD, **regenerate all scene + addon typings** (`generateAllTypings` → `generateTypings` + `generateAddonTypings`, every run), then run full 3-source diagnostic check (`[TS]`/`[CONV]`/`[GD]` prefixes). Self-contained: no separate `generate-typings` step needed. Flags: `--ts-dir`, `--gd-dir`, `--root-dir`, `--tsconfig`, `--godot-path`, `--project-root`, `--use-cache` (enable read-side cache skip — fast but content-hash freshness can serve stale output when outer types changed), `--no-cache` (disable cache entirely, no reads/no writes), `--emit-on-error`, `--no-emit` (dry-run + stale-check, no writes), `--no-check` (skip diagnostic pipeline). Default cache mode is **write-only**: every run converts fresh (correct w.r.t. cross-file type changes) but records results for reuse by `watch` / ts-plugin / the check phase. Source maps stored in cache dir. Requires `--tsconfig` for TS diagnostics; requires `--godot-path` + `project.godot` for Godot check.
- `tstogd initial-convert-gd-to-ts <files...>` — One-shot bulk GD→TS conversion for the initial migration of an existing GDScript project (`--ts-dir`, `--gd-dir`, `--root-dir`, `--registry`, `--unsafe-use-any`, `--emit-on-error`, `-f, --force`). All conversion helpers always run; no per-helper disable flag. **Default-safe**: existing `.ts` outputs are NOT overwritten — the command lists each skipped path at the end of the run, prints a `Pass --force to overwrite` hint, and exits non-zero. `--force` clobbers existing `.ts` files.
- `tstogd watch` — Synchronize shared-package links, then watch and auto-convert (`--root-dir`, `--ts-dir`, `--gd-dir`, `--tsconfig`, `--typings-dir`, `--godot-path`, `--project-root`, `--emit-on-error`, `--no-check`). Watches `.ts` + `.tscn`/resources/assets/`project.godot`; reconverts changed `.ts` and regenerates typings (full on first run, incremental after — so editing a scene refreshes its scene typings live). After each file-change batch settles (1000ms check debounce), runs full diagnostic check + clears console, then the **error-driven self-heal** (see "Type-Environment Dependencies"): files whose diagnostic signature changed without being in the converted batch are reconverted in memory and rewritten on byte diff, with ONE check rerun. Source maps stored in cache dir. Byte-compare-before-write: identical output skips the write and the per-file Godot validation. Residual harmless staleness (no error signal) persists — user docs recommend `convert` (fresh-by-default) after a watch session for byte-exact freshness.
- `tstogd validate-gd <files...>` — Run Godot CLI `--check-only` validation on `.gd` files (TS paths auto-resolve to their corresponding `.gd`), remap errors back to TS positions via cached source maps, and exit non-zero on any error diagnostic. Flags: `--godot-path`, `--project-root` (default `.`).
- `tstogd generate-typings <files...>` — Generate the per-script `.gd.d.ts` / `.tscn.d.ts` / `_resources.d.ts` / `_index.d.ts` tree for scene typings. Flags: `-o, --output` (override the resolved `typingsDir`), `--typings-dir`, `--root-dir`, `--tsconfig`.
- `tstogd generate-gdscript-global-typings` — Generate the bundled-class typings tree from Godot XML docs (`--godot-source <dir>` reads a Godot source tree's whole class reference via `godotSourceDocDirs()` in `src/typings/xml-parser.ts` — `doc/classes` first, then every `modules/*/doc_classes`, then every `platform/*/doc_classes` (the three roots Godot's own `doc/Makefile` reads; the platforms add the seven `EditorExportPlatform*` classes), each sorted by name; `yarn generate:godot-typings` uses it on `vendor/godot`, and so does `tests/typings/godot-docs.test.ts`, so the two cannot drift. `mono`'s `CSharpScript` comes along; excluding it would need a hand-kept list. Also `--docs-dir <dirs...>` variadic, appended after the source dirs — accepts one or more dirs covering `doc/classes/`, `modules/gdscript/doc_classes/`, etc.; `--output-dir`, `--override-dir`, `--no-default-overrides`). Writes `classes/`, `godot-class-registry.json`, and copies the bundled static `globals/` folder + `index.d.ts` into the output dir (skipped when output dir IS this package's own `typings/`).
- `tstogd generate-addon-typings` — Generate typings for GDScript addons in `addons/` (`-o, --output`, `--root-dir`)
- `tstogd open-editor` — Open a .gd file in an external editor as the corresponding .ts file. Required: `-f, --file`, `-e, --editor-cmd`. Optional: `-l, --line` (GD line, default 1), `-c, --col` (GD col, default 1), `-p, --project` (Godot project dir). Editor-command placeholders: `{tsFile}`, `{tsLine}`, `{tsCol}` — remapped via cached source maps.
- `tstogd clear-cache` — Clear the conversion cache: sweeps every entry in `cacheDir` except `.gdignore` and `cache.json.tmp-*` (another process's save between write and rename), then replaces `cache.json` with an empty manifest. Flag: `--force` drops both exemptions and keeps only `cache.json` (`.gdignore` is recreated by the same `save()`), which is the only way a tmp file orphaned by a crash gets collected — a tmp file is indistinguishable from a live save, so the user makes that call. A plain run lists spared tmp files so they're never invisible. Replacing rather than deleting is deliberate — `watch`/ts-plugin holders subscribe to `change`/`add` only, so an unlink would leave their in-memory manifest intact and let their next `save()` restore every entry. Verifies by reading the manifest back, since `save()` swallows its own write failures.

## Implementation Status

- [x] Object shorthand properties (`{ foo }`) emit dictionary entries (`{"foo": foo}`), including mixed and nested literals.
- [x] TS-to-GD converter (fixture pairs in `tests/fixtures/ts-to-gd/`): classes, properties, methods, signals, enums, control flow, expressions, operators (incl. `gd.ops.rem` for `%`), comments (`//` `/** */` `/* */`), await + `Promise<T>` return unwrap, lambdas, match, dict (`gd.dict` for non-string keys), gd.ops/as/signal/getset, source maps, shared tstogd libraries, variadic parameters (`...args`), `gd.is()` primitive type checks, plain-object member reads → `.get()` auto-conversion (universal on plain object types; undefined-based fallback elsewhere), decorators (bare names, `@exports` plural alias), Callable `.call()` rewrite, template literal flattening, abstract classes, `static FOO` → `static var FOO` (mutable statics), `readonly` is TS-only and emits `var` (class-level `const` comes from `export const X` inside the paired namespace block), member ordering preserved
- [x] GD-to-TS converter (fixture pairs in `tests/fixtures/gd-to-ts/`): same features in reverse, local scope tracking, async detection, inner classes, GodotClassRegistry for `this.` resolution, conversion helpers (signal handler type inference, operator fix, explicit convert, extends type, nullable phases A/B/C/D, ready-field-types), global enum constant qualification (`KEY_F21` → `Key.KEY_F21`), variadic parameters, `gd.is()` for primitive `is` checks, shorthand-literal expansion (`&"..."` `^"..."` `$Node` `%UniqueNode` `:=`), `super()` / `super.method()` round-trip, implicit `this.` insertion for own / inherited members (for an engine base, `GodotClassRegistry.getAllMembers()` supplies methods, properties, signals, constants AND enum values — so a bare inherited `CONNECT_ONE_SHOT` / `PRESET_FULL_RECT` takes the same `this.X` path as `NOTIFICATION_READY`, valid through the generated `StaticProps` statics merge, and converts back to `self.X`, or `ClassName.X` in a `static func` — Godot accepts both. `resolveAllInheritedMembers` in `gd-to-ts/context.ts` is the method's only consumer. Pinned by the gd-to-ts `inherited-constants` fixture, type-checked by the converted-project test)
- [x] AST types generated by @asgerf/dts-tree-sitter (gdscript + godot-resource)
  - Post-processed by `scripts/fix-tree-sitter-types.js` for TS 5.9 `erasableSyntaxOnly`
  - Regenerate: `yarn generate:ast-types`, `yarn generate:resource-ast-types`
- [x] Typings generation (classes, scenes, godot-docs with overrides/ system)
  - **File-independent architecture**: each .tscn/.ts/.tres generates its own .d.ts independently
  - Hybrid flat+tree type system: named type aliases per node with `[__node_type]`, `[__node_parent]`, `[__node_children]`, flat descendant paths
  - `[__node_root]`: string (root node name) for `/root/` path resolution
  - `[__node_extends]`: lazy scene inheritance via `__node_extends` symbol (no `Omit` overhead)
  - `get_node()`/`get_node_or_null()`/`has_node()`/`get_child()` overloads via module augmentation per script class
  - `get_node('/root/...')` absolute path support via `_GDGetRootNode`/`_GDFindRootTree`/`_GDCreateRootTree`
  - `get_parent()` typed via `[__node_parent]` tree reference
  - `GodotGroups` interface: per-group named interfaces (`__GodotGroup_X`) for typed `get_nodes_in_group()`, `get_first_node_in_group()`, group action methods
  - Sub-resource chain parsing for TileMap → TileSet → TileSetScenesCollectionSource
  - `GodotResources` interface: `.tscn` → `PackedScene<_GDTreeNode<Tree>>`, `.gd` → `typeof Class`, `.tres` → `gd_resource type` header
  - `uid://` keys: every `GodotResources` entry is also emitted under the resource's Godot UID (same value), so `load`/`preload`/`change_scene_to_file` resolve uid paths to the exact type. UID resolved by `resolveResourceUid` (scene-utils.ts): `.uid` sidecar (scripts/shaders) → `.import` sidecar (imported assets) → `.tscn`/`.tres` header. No UID found → only the `res://` key is emitted (uid keys appear once Godot has imported the project). `GodotScripts`/`GodotSceneTrees` are left `res://`-only (internal parser lookup tables)
  - Asset resources bundled into single `_resources.d.ts` (not individual files) for faster TS parsing
  - `ScriptPaths` pre-computed type alias to avoid repeated `_GDGetTreePaths` evaluation
  - `StaticProps` (`Omit<typeof ScriptClass, 'prototype' | keyof Function>`) for static field access on instances
  - Autoload singletons from `project.godot` → global `const` declarations (both `.gd` scripts and `.tscn` scenes), `uid://` resolution via `.uid` files
  - Unique name nodes (`%Name`) accessible from every subtree in the scene
  - **Addon typings** (`generate-addon-typings`): converts `addons/*.gd` → `.ts` via GD-to-TS, generates `.gd.d.ts` with global classes/enums/GodotScripts entries. Two-pass: convert all, then scan with TS program for cross-file resolution.
  - **Incremental generation** (`generateFileTypings`): per-file `.gd.d.ts`/`.tscn.d.ts` regeneration for watch mode (full generation only on first run, addon typings only on first run)
  - **Non-Node scripts excluded**: scripts that don't extend Node (e.g. `extends Resource`) skip tree navigation typings (ScriptTree, `get_node` overrides, `__Trees` interface)
  - **Value type interfaces** (Vector2, Color, Rect2, Packed*Array, etc.): generated with instance interface + `*Constructor`interface +`declare const`. No `new` — constructors are call signatures only (matches GDScript)
  - **Nullable reference types**: properties and method returns of reference types (Node, Material, Texture2D, etc.) are emitted as `T | null` in generated `.d.ts` files. Value/variant types (Vector2, Color, int, float, etc.) stay non-nullable. A type is a value type if its Godot XML docs include a copy constructor (a constructor with a single parameter of its own type). Both `valueTypes` and `constructorTypes` sets are derived from parsed XML at generation time (no hardcoded lists). `isNullableGodotType()` in `godot-docs.ts` determines nullability based on the derived value types. Nullability is applied at 4 emit sites in `godot-docs.ts` (properties, method returns, signal parameters, etc.). Overrides in `typings-overrides/` can restore non-null for specific members (e.g. `node.d.ts` overrides `get_tree(): SceneTree`, `get_viewport(): Viewport`, `get_window(): Window`).
  - **`GodotScenes` interface**: global interface in scene typings mapping scene resource paths (`res://...`) to root node types. Complements `GodotSceneTrees` (tree types) and `GodotResources` (PackedScene types).
  - **Key-union aliases in `_index.d.ts`** (emitted by `generateIndexTypingContent()` inside `declare global`, alongside the six base interfaces): `GodotScriptName = keyof GodotScripts`, `GodotSceneTreeName = keyof GodotSceneTrees`, `GodotSceneName = keyof GodotScenes`, `GodotResourceName = keyof GodotResources`, `GodotGroupName = keyof GodotGroups`, `GodotConnectionSceneName = keyof GodotConnections`. `keyof` is resolved lazily, so the aliases pick up entries merged in by per-file `.tscn.d.ts` / `.gd.d.ts` / `_resources.d.ts`. Users can type function args as `path: GodotResourceName`, `group: GodotGroupName`, etc. for autocomplete + typo-checking. Emitted once — no per-file duplication.
  - `[__variant_converts]` on value-type instance interfaces: union of types accepted by single-parameter "from" constructors (e.g. `Vector2[__variant_converts]: Vector2 | Vector2i`). Enables `gd.as(val, Target)` type narrowing
  - `readonly prototype: ClassName` on `*Constructor` interfaces enables `v instanceof Vector2` type narrowing
  - Packed array types get `[Symbol.iterator](): IterableIterator<ItemType>` (item type inferred from `append(value: T)` method signature) for typed `for (const x of arr)` loops

## Type-Environment Dependencies (cache staleness)

The TS→GD cache (`ProjectCache`) keys on own-file content hashes, but emitted `.gd` depends on types resolved **across files** — a change in an imported file or a generated/global `.d.ts` can make a "fresh" cache entry silently stale. Audit of all checker-dependent emit paths:

**Output-changing** (stale = wrong `.gd` bytes):

1. **Plain-object member access → `.get()`** — DEFUSED as a staleness hazard: standalone READS on plain TS object types always emit `.get(...)` regardless of optionality (`access-rewrite.ts` isPlainObjectType; assignment targets / chains / callees / class fields keep dot). The decision depends only on coarse class-vs-plain-object classification, and `.get()` exists on BOTH Dictionary and Object, so even a stale classification still runs. Undefined-based fallback remains for other object kinds.
2. **`.call()` insertion** — `self.x()` vs `self.x.call()` decided by whether the symbol's declaration is a `PropertyDeclaration` (may be inherited from a base class in another file); `fn()` vs `fn.call()` decided in `callable-call.ts` by the callee's declaration and the call/construct signatures of a possibly-imported type. A name is left alone when it resolves to a method, a function declaration, or an **ambient `VariableDeclaration`** — the last covers the 30 value-type constructors, which the typings spell `declare const Vector2: Vector2Constructor` and which therefore carry call signatures, no construct signature, and a declaration kind otherwise identical to a local holding a lambda. Dropping that clause emits `Vector2.call(x, y)` for every `Vector2(x, y)` in a real project; see the fixture blind spot under Known Edge Cases.
3. **Annotation classification** — every written annotation resolves through `classifyTypeReferenceName` (`common/gd-names.ts`): emitted only if the alias-followed symbol declares a `class`/`enum`. Re-kinding `Foo` between `class`/`interface`/`type` in another file flips `var x: Foo` ↔ `var x`. Stale annotation of a no-longer-class = GD parse error.
4. **`gd.getset` type inference** — fallback emits `checker.typeToString()` of the setter-param / initializer type — fully cross-file (`gd-getset.ts` resolveGetsetType). That fallback cannot return `int`: TypeScript erases `type int = number` for intrinsic types, so a `value:` referring to an `int` member resolves to bare `number` with no symbol and no `aliasSymbol`, and `int`-ness survives only in the declaration's type NODE. `value: this.e` with `get e(): int` therefore emits `var f: float = self.e` — pinned by the `getset` fixture, and only visible once a fixture program loads the typings. `isIntType` / `isFloatType` (`common/index.ts`) cannot help here for the same reason. The spelling is now translated by `provableGdType` rather than emitted verbatim with a three-way string remap: a resolved type proves a GD type only when it is a primitive (`number`→`float`, `boolean`→`bool`, `string`→`String`) or an engine name the user has not redeclared — both paths ask `engineTypeName()` (`common/gd-names.ts`), so a user's `type Color = {...}` drops on BOTH paths instead of claiming Godot's `Color` for a Dictionary, and the `Object` ↔ `GodotObject` rename (`src/converter/AGENTS.md`) applies to both. `T | null` is read through `getNonNullableType` first: a union has no symbol, and without `T`'s declarations `GodotObject` could not be recognised as the typings' class. Everything else drops; `value: this.points` with `points: int[]` used to emit `var g: number[]`, which Godot cannot parse. **Arrays never survive this step.** The scalar `number`→`float` guess is safe because Godot converts an int to a float on assignment, but `Array[T]` is invariant, so the same widening is rejected outright: `Array[float]` refuses `Array[int]`, and `Array[String]` refuses `Array[StringName]` (`type StringName = String` erases exactly like `type int = number`). A resolved type cannot tell those apart, so no array is answered here at all — a WRITTEN `int[]` still becomes `Array[int]` through the node path. Both Godot rejections were caught by `fixtures-godot-validate`, not by the string comparison. Pinned by the `getset` fixture (`j`, `k`, `tint`/`l`).

**Diagnostics-only** (stale = wrong cached errors; bytes unaffected): Promise misuse (unawaited call, `.then`/`.catch`), `undefined`-typed argument, `||`/`&&` as non-bool value, `in`-operator RHS classification (all in `expressions.ts`).

Everything else is syntactic (literals, operators, control flow, import→preload path resolution). Reach is total — any property access, call, or annotation touching a non-local type qualifies — so there is no cheap per-file "uses outer types" test; verifying any one decision needs a live checker (= built program), at which point re-running emit is the natural freshness check. TS's own incremental cache (tsbuildinfo/BuilderProgram) cannot be reused for this: it assumes type-independent emit (its signature-text cutoff misses `c→b→a` flow-through type changes) and treats any global/ambient `.d.ts` change as all-files-affected.

**Mitigation strategy (implemented):** with the universal `.get()` rule, every remaining _dangerous_ stale output surfaces as a fresh error each watch check cycle (TS diagnostics recomputed from the live program; Godot validates the actual on-disk `.gd`; decisions 2–3 fail visibly, see above). Watch mode exploits this via **error-driven self-heal** (`src/watcher/heal.ts` primitives, `src/watcher/check.ts` CheckRunner orchestration): files whose per-file diagnostic signature (severity+message, positions excluded) changed without being in the just-converted batch are reconverted in memory; if bytes differ they're rewritten and the check reruns ONCE per cycle. Suspects that surface only in that second pass (a heal-write moving another file's Godot diagnostics) are carried over as pre-seeded suspects and a recheck is requested — converges because each cycle strictly shrinks the set of files whose disk bytes differ from program output. Check cycles never overlap (in-flight guard with re-schedule; heal writes files, so interleaved chains could tear writes); `Watcher.stop()` awaits the in-flight cycle. `convert` (fresh-by-default) remains the byte-exact guarantee. **Residuals:** converter-only diagnostics caused by dep changes (Promise misuse, `||`/`&&`-as-value) produce no fresh TS/Godot signal and unchanged emit → stay stale until the file is edited or `convert` runs; harmless-stale outputs (e.g. missing newer annotation) also persist — watch guarantees _error-visible consistency_, not byte-freshness. Without a registry, `.get()` rewriting applies only to anonymous object literals (named types can't be proven non-Godot — rule 11).

## Known Edge Cases

Subsystem notes live next to the code, in `AGENTS.md` files (each with a one-line `CLAUDE.md` that imports it, so Claude Code loads the notes when it reads a file in that directory):

- `src/converter/AGENTS.md` — conversion rules (TS ↔ GDScript) and edge cases shared by both directions
- `src/converter/ts-to-gd/AGENTS.md` — TS → GD edge cases
- `src/converter/gd-to-ts/AGENTS.md` — GD → TS edge cases, conversion helpers, tree-sitter quirks
- `src/typings/AGENTS.md` — Godot / scene / addon typings generation
- `src/ts-plugin/AGENTS.md` — TS language service plugin
- `tests/AGENTS.md` — fixture harness guarantees

Cross-cutting edge cases (Godot validation, configuration, shared packages):

- Godot validation autoload filtering: `--check-only --script` doesn't load autoloads (bug #80319), two error formats: `"Identifier not found: X"` and `"Identifier "X" not declared in the current scope."`, filtered in both parsed and unparsed error paths
- Godot validation duplicate class filtering: `Class "X" hides a global script class` when tmp validation copy coexists with original .gd file, filtered via `isDuplicateClassFalsePositive()`
- `tstogd.json` `exclude` option: renamed from deprecated `ignore`. Glob patterns for files/folders to exclude from all CLI commands
- `tstogd.json` config: `godotVersion`, `registryPath`, and `sourceMap` were removed. Source maps are always generated. `disableGodotLint` disables Godot executable validation. `lib` marks shared packages, and `externalPackages` configures plain folders or custom mount names.
- `tstogd.json` `converterOptions.generateGlobalClassTypes` (boolean, default `false`) toggles the typings-generator layout for non-anonymous classes. `false` → module-scoped (`export class Foo` requires `import`); `true` → `declare global { class Foo extends ScriptClass }` (legacy / pre-refactor). Anonymous classes are always module-scoped. Addons override this to `true` unconditionally — addon consumers expect bare-name access. In the module-scoped layout GD→TS adds the missing `import { Foo } from "./foo"` lines afterwards (`injectMissingImportsForProject`, `src/converter/gd-to-ts/inject-imports.ts`): it type-checks the freshly written files and imports every user class a "cannot find name" diagnostic names. Those diagnostics come in FOUR codes, not two — `Cannot find name` (2304) and `Cannot find namespace` (2503), plus the "Did you mean 'Y'?" forms TypeScript switches to whenever a similar name is in scope (2552, 2833). The class being converted is often that similar name, so `class Enemy2 extends Enemy` reports 2552; listening for the plain forms only left every such base without its import, and the file uncompilable
- Shared-package model (`src/external-packages/index.ts`): npm dependencies whose root `tstogd.json` has `lib: true` are discovered before `convert` and `watch`. Library dependencies are traversed recursively and linked as separate packages; tstogd does not bundle one package into another. Explicit `externalPackages` entries add plain folders or override mount names. A custom mount does not rewrite paths already emitted in a prebuilt library, so a transitive dependency imported by that library must keep its expected mount name. Package roots are symlinked into the fixed, non-hidden `tstogd_modules` directory. The link step creates `node_modules/.gdignore` to prevent duplicate Godot scans. Stale managed symlinks are removed. Regular files and directories are never overwritten. Colliding mount paths and package `tsDir` or `gdDir` paths outside the package root fail loudly. All project scanners ignore `tstogd_modules`.
- `lib: true` means the package builds itself once and publishes the complete package root: TypeScript source, generated `.gd`, scenes, resources, and Godot-generated UID files. Consumers never convert dependency source. Godot scans the linked package as a unit, so global classes and resources do not depend on the TypeScript import graph. UID stability is the package's responsibility.
- TS→GD converter `ConvertOptions` carries `tsDir`, `gdDir`, `projectRoot`, `lib`, and resolved external package mappings. CLI, watcher, checker, self-heal, and ts-plugin conversion paths pass the same values.
